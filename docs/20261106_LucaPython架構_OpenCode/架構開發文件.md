# LucaPython 架構開發文件

> 這是 `..\LucaAWS`（Node.js/Next.js 版）的 **Python 翻版**。
> 目標：本機用 **Docker + Python(FastAPI) + PostgreSQL** 測試執行，完成後**一鍵部署**到 AWS（ECR → ECS Fargate → ALB）。
> 本文件是「先架構、後程式」的依據；第 8 節是實際開發順序與驗收標準。

|---|---|

## 3. 本地端開發架構（Docker 可測試執行）

```
瀏覽器 / curl
    │ http://127.0.0.1:8000
    ▼
本機容器 luca-python（gunicorn + UvicornWorker, :8000）
    │ 加入 docker network `shared-network`
    ▼
postgres17 容器（PostgreSQL 17, :5432）→ database `awsLucaPysn`
```

要點：

1. **直接用正在跑的 `postgres17`**，不再另建資料庫服務；新資料庫名稱 `awsLucaPysn`（與正式區同名，指令與程式碼不用改）。
2. 容器內連 DB 用 **hostname `postgres17`**（`shared-network` 上的 DNS alias），不是 `localhost`。
   `localhost` 在容器內指容器自己，一定連不上。
3. 本機跑 `python -m uvicorn app.main:app` 時，DB host 用 `localhost`（Windows 端映射 5432 已公開）。
4. 與 Node 版不同的地方：Node 版本機 5432 被封 → 走 Neon 的 HTTP transport（443）。
   Python 沒有等价的 HTTP transport，所以**本機一律走 Docker 内的 PostgreSQL**；正式區在 VPC 內可出 5432，所以 Neon pooler 可用。
5. `docker-compose.yml` 兩種用法：
   - `profiles: [external-db]`：只跑 app，连既有 `postgres17`（預設，符合「開發時直接使用」）
   - `profiles: [bundled-db]`：自附 postgres 服務（要整套可攜、換機器時用）

## 4. 正式區架構（AWS，一鍵部署）

```
外部 client → Route53/直接 DNS
    │ HTTP :80
    ▼
ALB `luca-python`（internet-facing, ap-southeast-2, SG 放行 0.0.0.0/0:80）
    │ listener :80 → default forward
    ▼
Target group `luca-python`（TargetType=ip, Port 8000, HealthCheckPath=/api/health）
    ▼
ECS Fargate task（awsvpc, 1024 CPU / 2048 MB, desired=1, enableExecuteCommand）
    │ gunicorn :8000
    ▼
PostgreSQL（Neon pooler endpoint，或備選 RDS）
```

必須保留 Node 版踩過的坑（Python 版同樣適用）：

- **ALB 要有自己的 SG** 並放行 `0.0.0.0/0:80`；用 VPC default SG 會「控制面全綠、資料面不通」。
- **VPC 要有 IGW + `0.0.0.0/0 → igw` 路由**：Neon 在 AWS 之外，task 連不出去就一定 timeout。
- **task 的 subnet 要 `MapPublicIpOnLaunch=true`**（或走 NAT），否則連 Neon 失敗。
- **Secrets Manager 由「執行角色」讀取**（`secrets[]`），`AmazonECSTaskExecutionRolePolicy` 不含 secrets 權限，要自己補 policy。
- **health check 一律 200**：回 500 會讓 ECS 把任務判為 unhealthy 而不斷重啟。
- **healthcheck 指令**：`python:3.12-slim` 沒有 `wget/curl`，改用 Python 一行 `urllib.request`；ECS `healthCheck` 同樣用 python（不能靠 wget）。
- Fargate platform version 用 `LATEST`（`1.0.0` 會被拒）。
- `TargetType=ip` 時，service 的 `loadBalancers` 一定要有 `containerName/containerPort`。

## 5. 資料庫策略（本地 Docker ↔ Neon 對應）

| 環境 | 連線 | 資料庫 | 命名 |
|---|---|---|---|
| 本機開發 | `postgres17` 容器（`shared-network`），user `admin` | `awsLucaPysn`（新建） | `postgresql://admin:***@postgres17:5432/awsLucaPysn` |
| 正式區（Neon，預設） | Neon 新專案 `luca-python` 的 pooler endpoint | **`awsLucaPysn`**（與本機同名） | `postgresql://neondb_owner:***@ep-...-pooler.<region>.aws.neon.tech/awsLucaPysn?sslmode=require` |
| 正式區（備選 RDS） | RDS private endpoint（VPC 內 5432 直通） | `awsLucaPysn` | 由 `aws/rds.py` 建立 |

建議與注意事項：

1. **Neon 建獨立專案**（`luca-python`），不要共用 `luca-web-vercel`：兩應用共用同一 compute 會互相影響（autoscaling、连接数、Quota、branch 限額），而且免費方案的 `branches_limit=10` 很快被吃滿。
2 **資料庫名稱 `awsLucaPysn` 含大寫**：PostgreSQL 未加引號會_fold 成小寫。連線字串裡的路徑位置不受影響，但 `CREATE DATABASE "awsLucaPysn"` 與 `search_path`/`current_database()` 比較時要留意；程式一律透過 `DATABASE_URL` 連線，不會手寫表名，所以實務安全。若要完全避免歧義，正式區可改用全小寫 `aws_luca_pysn`（文件與程式兩者都支援）。
3. **Neon 的 pooler 是 transaction mode pooling**：不支援 session 級行為（`SET`、prepared statements、`LISTEN`）。`app/db.py` 預設 `prepare=False`，`scripts/migrate.py` 走「直接連線」（不加 `-pooler`）。
4. **schema 用 `scripts/migrate.py` 套**，不在請求路徑建表。本機直接對 docker 跑；正式區在 VPC 內透過 ECS Execute Command 跑：
   `python scripts/migrate.py`（鏡像內已含 `scripts/` 與 `schema.sql`）。
5. `items` 表結構與 Node 版完全相同（`id/title/body/created_at`），方便兩邊資料互相比對。

### 8.1 `.bat` 的 1024 bytes 塊限制（實測得到的規則）

cmd 讀 `.bat` 是 1024 bytes 一塊：若邊界落在多字节（UTF-8）字元中間，或一整行跨越邊界，
該行會被切開而報 `not recognized as an internal or external command`。
實測過兩個觸發點：

1. 中文字元被 1024 邊界切開（`gitGithubPush.bat`）→ 解法：`.bat` 全 ASCII，中文訊息放外部 UTF-8 檔（`gitGithubPush.msg.txt`，key=value，用 `for /f` 載入 `M_*` 變數）。
2. 一整行跨越邊界（`deploy.bat` 的 `python scripts/dump_data.py --out="..."` 在 3072 字節附近被切開）→ 解法：把 `.bat` 壓在 1024 bytes 以內，只做分派，邏輯與中文訊息放在 `aws/ops.py`（Python 印 UTF-8 沒問題）。

目前 `deploy.bat` = 499 bytes、0 個非 ASCII 字元、行長度最大 90；以后要加指令請加在 `aws/ops.py` 的 `ACTIONS`，不要讓 `.bat` 長大。

## 9. 風險與注意事項（Python 版特有）

1. **psycopg v3 vs psycopg2**：本機已裝 `psycopg2-binary 2.9.9`，但專案統一用 **psycopg v3**（`psycopg[binary,pool]`），
   因為 v3 才有內建 `ConnectionPool` 與 async。若要用本機已裝的環境跑，需 `pip install "psycopg[binary,pool]"`。
2. **gunicorn sync worker 與 async pool 不能混用**：`UvicornWorker` 才是 async 路；若改用 sync worker，`db.py` 必須用 sync pool（本專案用 sync pool + sync route，最穩，
   且在 transaction-mode pooler 下行為一致）。
3. **每 worker 一個 pool**：`GUNICORN_WORKERS=2` × `DB_POOL_MAX=5` = 最多 10 連線；Neon 免費方案的 connection limit 要注意。
4. **`.ps1` 檔要存成 UTF-8 with BOM**（PowerShell 5.1 讀沒 BOM 的 UTF-8 会把中文當成 ANSI，字串亂掉甚至解析失敗）。
5. **不 commit 任何含密碼的檔案**：`.env*`、`.aws-state/`、`neon-url.txt` 都在 `.gitignore`。
6. **本機 5432 對外網被封**：本機連 Neon 會 timeout（實測），所以本機測試一律走 Docker 的 PostgreSQL；正式區靠 VPC 出口。
7. **時區/時間戳**：`created_at` 用 `TIMESTAMPTZ`，Python 端一律當 UTC 處理，頁面顯示 ISO8601，避免 Node 版 `new Date()` 與 Python `datetime` 不一致造成的顯示差。
8. **健康檢查與 target group port**：Python 版 port 是 `8000`，若沿用 Node 版的 target group（port 3000）會一直 unhealthy。`aws/bootstrap.py` 建的 target group 是 `8000`，且名字不同（`luca-python`），不會與 Node 版衝突。
9. **Neon 的 SQL 只能走 SQL Editor 或 VPC 內任務**：本機連 Neon 的 5432 被封（見第 6 點），而用 personal API key 打 `console.neon.tech/api/v2` 的 SQL route 會 `404 this route does not exist`（實測 `.../databases/{db}/run_sql`、`.../branches/{b}/sql`、`/projects/{p}/sql`、`.../query` 全部 404）。可用的是 Neon Console 的 SQL Editor（443）或 VPC 內 one-shot 任務（`aws/run_once.py`）。
10. **`.bat` 的 1024 bytes 塊**：見 8.1 — `.bat` 保持全 ASCII 且 ≤1024 bytes，中文訊息由 Python（或外部 UTF-8 檔）輸出。
