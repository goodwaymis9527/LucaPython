# 思考紀錄

記錄這次的執行順序、判斷依據，以及「原本以為如何、實際發現如何」的差異，方便之後改進。

## 1. 執行順序（實際做了什麼）

1. 先寫架構文件（`架構開發文件.md`）→ 定案框架 FastAPI + Jinja2、port 8000、psycopg v3、state 檔獨立。
2. 建專案骨架：`requirements.txt` / `app/` / `scripts/` / `aws/` / `Dockerfile` / `docker-compose.yml`。
3. 本地資料庫：在 `postgres17` 建 `awsLucaPysn`。
   - 关键：資料庫名含大寫，`CREATE DATABASE awsLucaPysn` 會被 fold 成小寫；實際用
     `ALTER DATABASE awslucapysn RENAME TO "awsLucaPysn"` 保住大寫。
4. `python scripts/migrate.py` 建表 → `items 表存在=True`。
5. 起服務並跑 smoke test（容器內跑，見下方第 3 節）。
6. Neon：用 MCP 建立新專案 `luca-python`（`summer-breeze-11298508`，region `aws-ap-southeast-2`），
   資料庫 `awsLucaPysn`，逐句執行 `schema.sql` 建表，連線字串寫進 `LucaPython\.aws-state\neon.json`。
7. 補完 AWS 腳本：`status.py`、`exec.py`、`rds.py`、`netcheck.py`、`deploy.ps1`、`readme.md`。

## 2. 原本以為 → 實際發現

| # | 原本的判斷 | 實際情況 | 結論 |
|---|---|---|---|
| 1 | 本機連 `127.0.0.1:5432` 一定 `ConnectionRefused`（Docker 端口不通） | 那時 Docker Desktop 已經停了（`dockerDesktopLinuxEngine` npipe 不見）。Docker 恢復後，本機可以連 `postgres17` 的 5432，`migrate.py` 成功 | 「端口不通」是 daemon 關閉造成的假象；先確認 daemon 再判斷網路 |
| 2 | 本機連不出去 Neon（5432 被封） | 重新實測 `test_neon_conn.py`：`connection timeout`（不是 refused）→ 對外 5432 確實被封 | 本機只能接 Docker 的 PostgreSQL；Neon 只能由 VPC 內的 task 連 |
| 3 | 本機 8000 可給 app 用 | `ai-service` 容器已占用 host 8000（`docker ps` 看得见），`docker compose up` 報 `port is already allocated` | compose 改用 `8090:8000`；容器內部仍是 8000（AWS target group 用 8000，不受影響） |
| 4 | `psycopg.connect(..., prepare=False)` 可以關掉 prepared statement | `ProgrammingError: invalid connection option "prepare"`。`prepare` 是 cursor/execute 層的参数；連線層要用 `prepare_threshold=0` | `app/db.py` 維持 `cur.execute(..., prepare=settings.prepare)`（正確）；測試脚本改用 `prepare_threshold=0` |
| 5 | `JSONResponse(dict)` 直接回資料庫列就結束 | `TypeError: Object of type datetime is not JSON serializable` → POST 回 500 | `app/routers/api.py` 改走 pydantic `Item.model_validate(row).model_dump(mode="json")`，`created_at` 變成 ISO 字串 |
| 6 | Secrets Manager 的重複建立例外是 `ResourceNotFoundException` | 實際是 `SecretExistsException`（Code 同名） | `aws/secret.py` 的例外判斷改成 `SecretExistsException`（或字串含 `Exists`） |
| 7 | `aws_common.py` 的 docstring 只是文字 | `SyntaxError: 'unicodeescape' ... truncated \UXXXXXXXX escape`（`C:\Users` 裡的 `\U`） | docstring 改成 raw string（`r"""..."""`） |
| 8 | `docker build` 一次就過 | build 過，但 lint 警告 `JSONArgsRecommended`（CMD 是 shell 形式） | 刻意留 shell 形式，因為 `${PORT}` / `${GUNICORN_WORKERS}` 需要 shell 展開；已在 Dockerfile 加註解 |
| 9 | Neon 的 `run_sql` 可以整份 `schema.sql` 一次跑 | `cannot insert multiple commands into a prepared statement` | 逐句執行（與 `scripts/migrate.py` 的「逐句」設計一致） |

## 6. 這一輪的補強與踩坑（M3/M4 驗收 + 文件）

1. **`app/config.py` 讀取順序**：改為「真正的環境變數 > `.env.local` > default」。
   原本 `.env.local` 會蓋掉 `docker compose` 傳進來的 `PORT`，導致冒煙測試打到錯的端口。
2. **冒煙測試可指定 base**：`python scripts/smoke_test.py --base=http://127.0.0.1:8090`（或環境變數 `SMOKE_BASE`），
   不再寫死 8000。
3. **錯誤回應要印出 body**：原本 HTTPError 只回狀態碼，500 發生的時候看不到原因；改後可以看到實際例外。
4. **Windows 控制台編碼**：腳本印 `✔/✘` 在 cp950 會 `UnicodeEncodeError`，所以 `sys.stdout.reconfigure(encoding="utf-8")`。
5. **端口 8000 的誤判**：本機 8000 是 `ai-service` 容器，`luca-python` 用 8090。
   兩者都會回 `/api/health` 的 JSON，內容很像，容易以為是同一個服務；實測因此得到假的 `ok=true`。
   另外先前留著的 uvicorn 行程也會佔 `127.0.0.1:8000`，要確認 `netstat -ano | findstr :8000` 的 PID。
6. **表單測試的網址**：`index.html` 的 form `action="/api/items"`（不是 `/`），所以冒煙測試第 4 步改成
   form-encoded POST `/api/items` → 303；POST `/` 會拿到 405。
7. **新增檔案**：`deploy.ps1`（ASCII only，避免 PowerShell 5.1 讀無 BOM 的 UTF-8 亂碼）與 `readme.md`（一行指令速查）。
8. **PowerShell 字串陷阱**：`"postgresql://$env:DB_USER:$env:DB_PASSWORD@..."` 會被解析器把 `:` 吃掉（實測輸出變成 `postgresql://<password>@host`）。
   改用 `-f` 格式化：`'postgresql://{0}:{1}@{2}:5432/awsLucaPysn' -f $env:DB_USER, $env:DB_PASSWORD, $pgHost`。
9. **`deploy.ps1` 讀 `.env` 而不是寫死密碼**：`Set-Item -Path "Env:NAME"` 才能真的寫進程序環境變數（`[Environment]::SetEnvironmentVariable` 在函式內不會反映到 `$env:`）。

10. **本機跑 `scripts/migrate.py` 的 host 要是 `localhost`**（`postgres17` 這個名字只在 docker 網路內部解析，本機直跑會 `getaddrinfo failed`）；

### 7.2 boto3 的參數陷阱（實測踩到並已修）

1. **SG ingress 的來源欄位**：boto3 沒有 `SourceGroup`；正確是 `SourceSecurityGroupName`（簡易寫法）或 `IpPermissions` + `UserIdGroupPairs`。
   簡易寫法也不能把 `SourceSecurityGroupId` 和 `FromPort` 併用：
   `InvalidParameterCombination: The parameter 'SourceSecurityGroupId' may not be used in combination with 'FromPort'`
   → `authorize()` 一律改走 `IpPermissions`；CIDR 要放 `IpRanges`（`CidrIp` 在 `IpPermissions` 內不是合法鍵）。
2. **`is_err_type()` 要正規化**：IAM 的 Code 是 `NoSuchEntity`／`EntityAlreadyExists`，但例外類別名帶 `Exception`；EC2 的 Code 帶句點（`InvalidGroup.Duplicate`）。兩邊都去掉句點與 `Exception` 後才比對得起來。
3. **`CreateTargetGroup` 沒有 `DeregistrationDelay*`**：draining 只能事後 `ModifyTargetGroupAttributes(Attributes=[{"Key":"deregistration_delay.timeout_seconds","Value":"60"}])`。
4. **`register_task_definition()` 只收 keyword arguments** → 要 `**build_task_definition(...)` 解包。
5. **`create_secret()` 的參數是 `Description`（大寫 D）**，不是 `description`。
6. **bootstrap 每節都要寫 state**：被 `PassRole` 這類錯誤打斷時，前面已建好的 ARN 才不會丟失（新增 `flush()`）。

### 7.6 ECS Exec 的實際限制

`aws/exec.py` 原本假設能拿到 stdout，但 boto3 的 `ExecuteCommand` 只收 `interactive=True`：

```
InvalidParameterException: Interactive is the only mode supported currently.
```

`interactive=True` 只會回 session（sessionId / tokenValue / streamUrl），stdout 要由 Session Manager plugin 串出來，而本機沒有 `session-manager-plugin`，也沒有 AWS CLI v2。
所以 `exec.py` 改成「建立 session + 印出要用 CLI 的指令」，真正的輸出改用 `aws/run_once.py`：`RunTask` + `containerOverrides.command` → 任務跑完從 CloudWatch logs 讀（需要 `ecs:RunTask`、`ecs:StopTask`）。

注意：一次性任務會計費到被停掉為止（Fargate 以 15 分鐘為單位），`run_once.py` 支援 `--stop`。

### 7.7 `deploy.ps1 -Step health` 的兩個 bug（已修，commit `a4dfc2e`）

1. **ALB 那行完全不會印**：腳本比對的是 `"alb_dns_name"`，但 `aws_common.save_state()` 寫進 `config.json` 的鍵是 `albDns` → 正則永遠不匹配，所以輸出只有本機那行。改成 `ConvertFrom-Json` 後讀 `$cfg.albDns`（不再靠正則，键名一改就失效這種脆弱性）。
2. **欄位讀錯**：`/api/health` 的回應是 `{ok, db:{...}, error}`，腳本讀 `$r.status` / `$r.host` / `$r.database`（這些不存在）→ 印出 `status= host= db=` 全空，看起來像容器沒在跑，其實容器有在跑且回 200。改成讀 `$r.ok`、`$r.db.env`、`$r.db.host`、`$r.db.database`、`$r.db.prepare`，並印 `$r.error`。
3. 另加 `-UseBasicParsing`（PS 5.1 的 `Invoke-RestMethod` 預設走 IE 引擎，無人值守時可能失敗）。

修正後的輸出（兩邊都探）：

boto3 形狀的兩個新踩點（已修，commit `5cb373c`）：

1. `RunTask` 的回應是 `tasks[]` / `failures[]`，**沒有** `task` 鍵。
2. `Task.containers[]` **沒有** `logStreamName`（Container shape 只有 name/exitCode/image/... ），stream 名稱要自己拼：`<awslogs-stream-prefix>/<family>/<taskId>`，也就是 `app/luca-python/<taskId>`。
3. `describe_task_definition` 的參數是 `taskDefinition`（收 ARN 或 `family:revision`），不是 `taskDefinitionArn`；`status.py` 之前用錯名字（所以那節一直印「還沒有 revision」其實是 list 的回應鍵 + 參數名都錯）。
