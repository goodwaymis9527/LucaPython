# 排錯紀錄

## 現象

```
PS D:\goodwaymis9527\LucaPython> docker compose up -d --build
no service selected
```

## 原因

`docker-compose.yml` 裡**每一個 service 都挂在 `profiles:` 下**：

| service | profile |
|---|---|
| `app`（luca-python，8090:8000） | `external-db` |
| `db`（luca-python-db，自附 postgres:17） | `bundled-db` |
| `app-own-db`（8001:8000，连自附 db） | `bundled-db` |

compose 的規則：service 有 `profiles` 時，只有該 profile 被啟用才會被選入；`docker compose up` 
沒給 profile → 選出的清單是空的 → `no service selected`。這不是錯誤，是「你沒說要跑哪一組」。

實測（改之前）：

```
docker compose config --services                 → (空)
docker compose --profile external-db config --services → app
docker compose --profile bundled-db config --services  → db, app-own-db
```

## 兩種跑法（原文檔就寫在開頭）

- A) 用既有 `postgres17`（本機開發常用，`shared-network` 已存在）
  `docker compose --profile external-db up -d --build`
- B) compose 自己起 db（換機器、整套可攜）
  `docker compose --profile bundled-db up -d --build`

## 已做的修改（让 plain 指令可用）

1. `.env` 尾端加了：

   ```
   COMPOSE_PROFILES=external-db
   ```

   compose 會自動讀同目錄的 `.env`，`COMPOSE_PROFILES` 就是預設啟用的 profile，
   所以 `docker compose up -d --build` 現在會選到 `app`（實測 `docker compose config --services` → `app`）。
2. `docker-compose.yml` 開頭補註解說明這件事；`.env.example` 也補上同一行範例。

> 想跑 B 組時：`docker compose --profile bundled-db up -d --build`（`COMPOSE_PROFILES` 與 `--profile` 會併入，不會互斥）。

## 環境現況（當時實際查的）

- `shared-network` 存在（compose 宣告 `external: true`，不存在會報 `network shared-network not found`）。
- `postgres17` 容器在跑（healthy），所以 A 組的 `DATABASE_URL` 指向 `postgres17:5432` 可用。
- `luca-python` 容器本來就 Up（4 hours, healthy），對應本機 8090；本機 8000 是 `ai-service` 用到的，別混淆。

## 驗證方式

```powershell
docker compose config --services          # 應該要看到 app
docker compose --profile external-db up -d --build
python scripts/smoke_test.py --base=http://127.0.0.1:8090
```
